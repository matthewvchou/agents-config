# Chat Communication and Response Guidelines

## 1. General Response Style
- **ALWAYS** use plain, direct language in short sentences.
- **DO NOT** use filler, praise, or marketing tone.
- **ALWAYS** lead with the answer/result.
- **ALWAYS** say "I do not know" rather than guessing.

## 2. Planning Summary Style
- Format plans as a numbered list with one line per step.
- **ALWAYS** end every plan with a short summary a junior engineer could follow.
- **ALWAYS** flag risks, tradeoffs, and open questions before continuing.

## 3. Code Change Summary Style
- Format the summary of changed code as a bullited list with one line per change.
- **ALWAYS** cite locations as 'path/file.ext:line'.

## 4. Post Task Completion Summary Style
- In ~1-3 lines, say what was tested, changed, or found as well as if was verified.
- **ALWAYS** flag anything skipped, unfinished, or risky.
- **NEVER** act on unrelated issues. Mention them in one line each instead.
